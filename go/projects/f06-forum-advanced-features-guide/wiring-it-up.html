Wiring it up and running it

cmd/lab/main.go is the process wrapper. Complete internal/lab/scenario.go to parse the documented mode, compose prepared components, own database/server lifetimes and handle shutdown. Do not open connections in init or discard returned errors.

Run procedure

go version
go mod tidy
go fmt ./...
go vet ./...
go test ./...
go build ./cmd/lab
go run ./cmd/lab demo
# After implementing the HTTP adapter:
go run ./cmd/lab serve
# In another terminal (curl.exe on Windows, curl elsewhere):
curl.exe -i http://localhost:3000/health
# After completing the container configuration:
docker compose build
docker compose up -d
docker compose logs
docker compose down

Initially the run and tests fail with TODO diagnostics. The compile-only command go test -run "^$" ./... checks scaffold compilation; it does not run the required behavior tests. Replace every failing placeholder with independently specified assertions.

Dependencies and configuration

The supplied starter needs only the standard library to compile. Add a reviewed dependency only when its preparation introduces it. Commit go.mod/go.sum, use the cohort-pinned Go 1.26 patch and follow the native compiler/container procedure for SQLite. Read the Go runtime policy from this path’s overview.

Troubleshooting

Symptom / Check
SymptomCheck
TODO failureExpected until the scenario and contract assertions are implemented.
Import path errorRun from the starter module root; keep its module and internal-package import paths consistent.
CGO or sqlite3 errorVerify the approved driver, compiler and CGO_ENABLED in the target build environment.
Hanging testClose response bodies, rows and servers; propagate cancellation; wait for worker completion.
