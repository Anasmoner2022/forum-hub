Go runtime and dependency policy

Go learning path. The required forum behavior matches the Node.js path; reading, commands, examples and unfinished code here use Go.

Target a cohort-pinned Go 1.26 patch. The local scaffold compiler is Go 1.26.2; this is a curriculum baseline rather than a claim to the newest release. Use one reviewed toolchain across supported hosts and containers.

Module workflow

go version
go mod tidy
go mod verify
go fmt ./...
go vet ./...
go test ./...
go build ./cmd/lab

At the relevant stage, select and install academy-reviewed versions with go get module@version, then commit go.mod/go.sum. Do not copy unreviewed latest pins or install all specialist packages in P01. Starters use the standard library until the learner introduces that stage’s dependency.

CGO and connection rules

  • Install a supported C compiler and enable CGO for the selected SQLite driver; Linux Docker is the reproducible fallback when a host lacks the native toolchain.
  • sql.DB is a connection pool. Configure foreign keys and busy timeouts for every ordinary SQLite connection, and key every encrypted connection before schema access.
  • Use tx methods inside a transaction; never mix db and tx calls for one atomic operation.
  • A CGO executable is not automatically a portable static binary: verify libc, architecture, shared libraries and non-root permissions in the runtime image.

Release preflight

Compilation checks do not certify finished implementations, native libraries or live providers. Pilot the Go route, resolve exact dependency pins compatible with the selected toolchain and test all preparation gates on the academy’s supported environments.
