Full specification

Required behavior

  1. Guest reads only published public content; member creates, comments and reacts; moderator additionally reviews pending posts and deletes/reports posts; admin additionally manages roles, reports, posts/comments and categories.
  2. Load current role from server-side database state for every authorized action; ignore role and owner IDs supplied by the browser.
  3. Permissions consider actor role, resource ownership, publication state and action. Pending/deleted content cannot leak through details, lists, counts or assets.
  4. Admin bootstrapping is a one-time operator procedure outside public registration; users never self-select admin. Prevent demoting or deleting the final administrator.
  5. Role promotion/demotion changes take effect on the next request; rotate/revoke session privileges according to P10 policy and test revocation. Guest returns 401 on writes; authenticated forbidden actions return 403.

Out of scope

Implement this focused artifact or named forum assignment. Optional extras are not required. No ORM or framework may replace the assessed logic. Use synthetic data and keep real credentials out of source, fixtures and logs. The Go and Node.js paths have the same domain behavior; this path implements it using the prepared Go tools.
