Step 2: Build private visibility-aware sections

Implement session-derived actor selection, tombstones and stable pagination.

Questions before writing

  1. What enters this component of Personal Activity Queries and Index Observatory, and which fields are trusted?
  2. Which invariant survives a failure?
  3. Do not use a requested member ID as the viewer.

Guided build

  1. Write an independent acceptance example for build private visibility-aware sections.
  2. Do not use a requested member ID as the viewer.
  3. Pending content is visible only under the permitted owner/role policy.
  4. Keep separate bounded page parameters and pass the trusted actor ID to every query; use sql.NullString or an equivalent explicit nullable representation.
  5. Implement the smallest typed boundary and record the policy you chose.

Self-check

A URL containing memberId=B still returns only A’s activity when A is authenticated.

Evidence to keep

Keep exact input, result and state/diagram evidence. If the self-check fails, trace this component before moving on.
