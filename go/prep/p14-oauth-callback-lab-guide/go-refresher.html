Go and subject refresher

The browser carries an authorization code, not a trusted identity. State binds the attempt to the originating browser; a stored PKCE verifier is supplied only during the server token exchange.

Go implementation notes

  • Draw the browser, forum and fake-provider sequence before wiring net/http handlers on separate ports.
  • Store a hashed browser-binding value, state, verifier and five-minute expiry; atomically consume the attempt using SQL before exchanging the code.
  • Use the reviewed golang.org/x/oauth2 options for S256; test provider errors, exact redirects and replays with the P13 client budgets.

Project-specific trace

Predict “Successful round trip”: matching browser, state, code and verifier should produce one token result. Contrast it with “Bad PKCE”.
