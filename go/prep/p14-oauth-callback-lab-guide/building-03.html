Step 3: Complete code exchange and failure paths

Implement the fake provider’s one-time code and verifier check, then connect the client adapter.

Questions before writing

  1. What enters this component of OAuth Authorization Code, State and PKCE Lab, and which fields are trusted?
  2. Which invariant survives a failure?
  3. Mark synthetic provider behavior clearly.

Guided build

  1. Write an independent acceptance example for complete code exchange and failure paths.
  2. Mark synthetic provider behavior clearly.
  3. An authorization error must not fall through to login success.
  4. Use the reviewed golang.org/x/oauth2 options for S256; test provider errors, exact redirects and replays with the P13 client budgets.
  5. Implement the smallest typed boundary and record the policy you chose.

Self-check

A missing verifier, denial or expired code leaves the session count unchanged.

Evidence to keep

Keep exact input, result and state/diagram evidence. If the self-check fails, trace this component before moving on.
