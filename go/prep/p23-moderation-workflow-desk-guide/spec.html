Full specification

Required behavior

  1. Posts move pending→published or pending→rejected; published→deleted by authorized moderator/admin. New posts remain private until approved; moderators cannot self-approve.
  2. Author sees their own pending/rejected submission; moderators/admins see review queues; public readers, filters and counts include published content only.
  3. A member submits a pending moderator-role request; admin approves or rejects it, promotes/demotes moderators, and records actor, reason and time.
  4. Moderator can delete a post or file a report to admin; admin receives a reports inbox, responds and resolves reports. Store reporter, post reference or retained snapshot, reason, response and status.
  5. Admin can delete posts and comments and create/delete categories. Deleting a category attached to any retained post returns 409; no silent removal may leave a post without its required category.
  6. Every transition checks expected current state and permissions inside a transaction; competing decisions yield one winner and a 409 conflict, preserving an audit trail.

Out of scope

Implement this focused artifact or named forum assignment. Optional extras are not required. No ORM or framework may replace the assessed logic. Use synthetic data and keep real credentials out of source, fixtures and logs. The Go and Node.js paths have the same domain behavior; this path implements it using the prepared Go tools.
