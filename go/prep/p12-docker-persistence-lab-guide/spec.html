Full specification

Required behavior

  1. Use pinned, cohort-approved Go builder/runtime images. Build in Linux with the reviewed module versions, CGO_ENABLED=1 and a C compiler; document runtime libc and architecture compatibility.
  2. Run as a non-root user with explicit writable data and upload directories; expose the documented app port and bind the server to 0.0.0.0 in the container.
  3. Persist the whole SQLite directory in a named volume, including WAL/SHM companion files when WAL is used; replace the container without losing data.
  4. Build .dockerignore excluding secrets, private keys, databases, local executables and unrelated academy guides. Never copy a Windows executable into a Linux runtime image.
  5. Practise a consistent backup using SQLite backup API or a stopped/closed database copy. Restore to a separate disposable location, verify migrations, foreign keys and row counts, and keep live data intact.

Out of scope

Implement this focused artifact or named forum assignment. Optional extras are not required. No ORM or framework may replace the assessed logic. Use synthetic data and keep real credentials out of source, fixtures and logs. The Go and Node.js paths have the same domain behavior; this path implements it using the prepared Go tools.
