Step 3: Count and explain contention

Query both counts, distinguish empty totals and test competing writers.

Questions before writing

  1. What enters this component of Reaction State Machine and Transactions, and which fields are trusted?
  2. Which invariant survives a failure?
  3. Do not multiply reactions by joining labels.

Guided build

  1. Write an independent acceptance example for count and explain contention.
  2. Do not multiply reactions by joining labels.
  3. A sync database operation blocks the Node event loop while running; keep operations short.
  4. Start competing requests with a barrier, wait for both, then read committed state; classify exhausted SQLite lock contention separately.
  5. Implement the smallest typed boundary and record the policy you chose.

Self-check

A fresh target displays 0 likes and 0 dislikes and remains readable after a lock failure.

Evidence to keep

Keep exact input, result and state/diagram evidence. If the self-check fails, trace this component before moving on.
