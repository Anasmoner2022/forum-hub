Step 2: Enforce transactional mutations

Choose a unique key and implement conflict-safe changes.

Questions before writing

  1. What enters this component of Reaction State Machine and Transactions, and which fields are trusted?
  2. Which invariant survives a failure?
  3. Database constraints protect against two handlers passing the same precheck.

Guided build

  1. Write an independent acceptance example for enforce transactional mutations.
  2. Database constraints protect against two handlers passing the same precheck.
  3. Make target existence and state change one coherent operation.
  4. Keep the target/member uniqueness constraint and execute changes on one sql.Tx; do not hold a transaction while calling external services.
  5. Implement the smallest typed boundary and record the policy you chose.

Self-check

Twenty concurrent set-like requests for the same member-target leave one row.

Evidence to keep

Keep exact input, result and state/diagram evidence. If the self-check fails, trace this component before moving on.
