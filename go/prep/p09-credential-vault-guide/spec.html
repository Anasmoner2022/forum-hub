Full specification

Required behavior

  1. Require email, username and password; normalize email by trimming and lowercasing under an explicitly documented academy policy; reserve a unique normalized username.
  2. Email length is at most 254, username 3–30 characters matching letters/digits/underscore, and password 12–128 Unicode code points; enforce a 1024-byte password input cap before expensive work.
  3. Use golang.org/x/crypto/scrypt with independent random salts and a versioned record. Training default: N=131072, r=8, p=1, 64-byte output, 16-byte salt. Bound simultaneous derivations to one initially and measure peak memory and latency before cohort launch.
  4. Use crypto/subtle.ConstantTimeCompare on equal-length derived byte slices. Reject malformed/excessive record parameters before derivation; return generic invalid-credentials messages.
  5. Never log raw passwords or hash records, never use reversible encryption for passwords, and rely on database uniqueness to settle competing registrations. BCrypt is an alternative only after equivalent prep and its byte-limit policy are reviewed.

Out of scope

Implement this focused artifact or named forum assignment. Optional extras are not required. No ORM or framework may replace the assessed logic. Use synthetic data and keep real credentials out of source, fixtures and logs. The Go and Node.js paths have the same domain behavior; this path implements it using the prepared Go tools.
