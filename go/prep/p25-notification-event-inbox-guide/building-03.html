Step 3: Protect and render the inbox

Build recipient-only listing/read actions and deleted-target tombstones.

Questions before writing

  1. What enters this component of Transactional Events and Notification Inbox, and which fields are trusted?
  2. Which invariant survives a failure?
  3. An inbox ID is not authorization.

Guided build

  1. Write an independent acceptance example for protect and render the inbox.
  2. An inbox ID is not authorization.
  3. Resolve current target visibility rather than rendering an old private snapshot publicly.
  4. Resolve current recipient and target visibility; use httptest to attempt another member’s list/read action by changing IDs.
  5. Implement the smallest typed boundary and record the policy you chose.

Self-check

Another member cannot read or mark the recipient’s notification by changing an ID.

Evidence to keep

Keep exact input, result and state/diagram evidence. If the self-check fails, trace this component before moving on.
