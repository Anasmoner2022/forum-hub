Go and subject refresher

An ID-token verifier checks signature and configured token policy; the application still binds the nonce to the consumed login attempt. GitHub identity comes from its authenticated API, not a decoded JWT.

type ProviderIdentity struct {
    Issuer string
    Subject string
    Email string
    EmailVerified bool
}
// Persist identity by issuer plus subject; linking is a separate authorized action.

Go implementation notes

  • Register both provider test applications and demonstrate exact callback URIs before the forum assignment.
  • Use coreos/go-oidc/v3/oidc for Google discovery and verification; configure issuer, client ID and permitted signing algorithms, verify expiry, then compare the attempt nonce.
  • Use the bounded oauth2 client for GitHub /user and verified-email lookup; never auto-link accounts by matching email alone.

Project-specific trace

Predict “Both providers”: fresh Google and GitHub test identities should produce each can create and later log into a local account. Contrast it with “Link conflict”.
