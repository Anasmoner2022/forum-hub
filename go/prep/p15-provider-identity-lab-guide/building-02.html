Step 2: Verify and normalize identity

Implement distinct OIDC and GitHub adapters and stable unique subjects.

Questions before writing

  1. What enters this component of Google OIDC, GitHub Identity and Account Linking, and which fields are trusted?
  2. Which invariant survives a failure?
  3. Do not trust a browser-supplied profile or unsigned payload.

Guided build

  1. Write an independent acceptance example for verify and normalize identity.
  2. Do not trust a browser-supplied profile or unsigned payload.
  3. A renamed GitHub login should still resolve the same local member.
  4. Use coreos/go-oidc/v3/oidc for Google discovery and verification; configure issuer, client ID and permitted signing algorithms, verify expiry, then compare the attempt nonce.
  5. Implement the smallest typed boundary and record the policy you chose.

Self-check

Wrong audience, wrong nonce and expired Google token all fail before account creation.

Evidence to keep

Keep exact input, result and state/diagram evidence. If the self-check fails, trace this component before moving on.
