Go and subject refresher

Ordinary go-sqlite3 does not implement database encryption. Use a separately reviewed SQLCipher-enabled build, verify cipher_version and apply the key before any schema access on each connection.

// Optional encrypted adapter contract:
// 1. Load a key from a protected file.
// 2. Open and key an SQLCipher connection before any read.
// 3. Verify cipher_version and schema access, then expose repository operations.

Go implementation notes

  • Build an isolated Linux CGO module with a reviewed SQLCipher driver and compiler. Do not import ordinary and encrypted drivers that register the same sqlite3 name into one executable.
  • Use a bounded single-connection sql.DB for the lab, set/key it before schema access and handle reconnection explicitly; transaction operations stay on one sql.Tx.
  • Use documented sqlcipher_export, verify schema metadata and foreign keys, then prove ordinary SQLite cannot read the encrypted target.
  • Rotate only disposable copies, verify old/new key behavior, and restore an encrypted snapshot with separate key custody.

Project-specific trace

Predict “Cipher engine”: query cipher_version in clean Linux image should produce nonempty supported cipher version. Contrast it with “Rotation/recovery”.
