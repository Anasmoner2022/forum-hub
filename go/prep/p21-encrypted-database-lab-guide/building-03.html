Step 3: Export and test real encryption

Key before first read and export a plaintext fixture to a separate encrypted target using documented API syntax.

Questions before writing

  1. What enters this component of Optional Live Database Encryption and Recovery Lab, and which fields are trusted?
  2. Which invariant survives a failure?
  3. Retain the plaintext disposable source until all checks pass.

Guided build

  1. Write an independent acceptance example for export and test real encryption.
  2. Retain the plaintext disposable source until all checks pass.
  3. Copy schema version/application metadata explicitly rather than assuming export copies pragmas.
  4. Use documented sqlcipher_export, verify schema metadata and foreign keys, then prove ordinary SQLite cannot read the encrypted target.
  5. Implement the smallest typed boundary and record the policy you chose.

Self-check

Right key reads expected rows; wrong/missing key and ordinary SQLite cannot read the encrypted target.

Evidence to keep

Keep exact input, result and state/diagram evidence. If the self-check fails, trace this component before moving on.
