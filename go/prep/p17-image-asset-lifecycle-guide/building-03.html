Step 3: Serve under the parent policy

Route asset IDs through a visibility check and correct headers; persist the storage directory.

Questions before writing

  1. What enters this component of Decoded Image Validation and Asset Lifecycle, and which fields are trusted?
  2. Which invariant survives a failure?
  3. Do not bypass the check with a publicly mounted upload directory.

Guided build

  1. Write an independent acceptance example for serve under the parent policy.
  2. Do not bypass the check with a publicly mounted upload directory.
  3. Content-Type comes from validation, not request headers.
  4. Use opaque server-generated names, an explicit MIME allowlist and parent visibility checks; compensate stored-file writes when the database transaction fails.
  5. Implement the smallest typed boundary and record the policy you chose.

Self-check

An authorized public viewer sees the image; a guessed private-parent asset ID is denied.

Evidence to keep

Keep exact input, result and state/diagram evidence. If the self-check fails, trace this component before moving on.
