Full specification

Required behavior

  1. Teach TLS handshake roles, private/public keys, certificates, issuer trust, SAN hostname validation and modern cipher negotiation before configuring the server.
  2. Generate a seven-day localhost development certificate with DNS:localhost and IP:127.0.0.1 SAN entries; never commit private keys. Read certificate/key paths from configuration.
  3. Use net/http.Server with crypto/tls and a minimum of TLS 1.2, current safe runtime defaults, mounted key material and explicit timeouts. Never disable certificate verification globally.
  4. Development clients trust the specific self-signed certificate with curl --cacert; a deployed site uses a valid hostname certificate from a trusted CA and a documented renewal process.
  5. Enable Secure session cookies in HTTPS mode, document HTTP-to-HTTPS redirect behavior and bind/mount permissions in Docker. Missing keys or mismatched certificate configuration fail startup clearly.
