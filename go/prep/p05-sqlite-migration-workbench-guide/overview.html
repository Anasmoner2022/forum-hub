Overview

Turn your reviewed ERD into a real SQLite database with versioned migrations, repeatable seeds and visible constraint failures.

Concrete deliverables

  • A migration runner, ordered SQL files and a persistent database
  • A migration journal and constraint demonstration transcript

Why build this?

Make the “Fresh migration” case observable and demonstrate the failure or boundary case “Changed migration”. A peer must reproduce the artifact, not just recognize an API name.

Prerequisites

  • P01: Go Language, Runtime and Module Lab
  • P04: Community ERD and Relational Schema Design

Reuse and what changes

  • P01: reuse its tested Go contracts; preserve their regression cases while adapting them to this project.
  • P04: reuse its tested Go contracts; preserve their regression cases while adapting them to this project.

Time and team

Plan about 12 focused learner-hours including reading, building and peer review.
