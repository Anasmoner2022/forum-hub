Full specification

Required behavior

  1. Accept decoded JPEG, PNG and GIF only, regardless of extension or declared MIME. Decode with Sharp; metadata inspection alone is not proof a compressed file is valid.
  2. Academy limits: width and height each 1–8192, at most 25,000,000 pixels per frame, at most 100 GIF frames and 100,000,000 total decoded pixels. Reject oversized or corrupt images with 422.
  3. Inspect metadata with strict decoder limits, then force bounded decode/re-encode. Retain JPEG/PNG/GIF output, strip irrelevant metadata, and preserve GIF animation within limits.
  4. Move validated data to generated opaque names outside the source/static root; store format, dimensions, byte count, owner and storage key. Serve via an ID lookup with verified Content-Type and nosniff; never expose filesystem paths.
  5. A post may have text and one image or text only. Publish the post only after validation and finalized file placement; database failure triggers file cleanup, and a reconciliation tool identifies crash leftovers.
  6. If moderation is later installed, pending/deleted post images must use the same visibility policy as their parent; an obscure filename is not authorization. Persist temp/final storage in Docker correctly.

Out of scope

Build this focused deliverable, not the complete forum. Features in the Level up chapter are optional and are not prerequisites unless the roadmap explicitly selects them. Do not replace a core learning task with a framework or finished service.

Use synthetic users and disposable test data during development. Keep a decision record when the brief allows a choice; the record must include an independently verifiable consequence.
