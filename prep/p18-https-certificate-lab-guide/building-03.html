Step 3: Package configuration and renewal assumptions

Mount key files read-only and document trusted-CA deployment and renewal.

Questions before writing

  1. Which input and trusted context enter this component of HTTPS, Certificates and Container Configuration?
  2. Which persisted or visible invariant must remain true if this step fails?
  3. Do not bake private keys into the image.

Guided build

  1. Write a small acceptance example for package configuration and renewal assumptions using this project's verification table.
  2. Do not bake private keys into the image.
  3. Certificate expiry must be visible in the operations worksheet.
  4. Implement the smallest boundary that satisfies that example; keep core logic in your own module and record your chosen policy.

Self-check

The container starts with valid mounts and fails clearly when the key path is missing.

Evidence to keep

Keep the exact input, observed result and state/diagram evidence that make this self-check independently reviewable. If the result differs, trace the component before continuing.
