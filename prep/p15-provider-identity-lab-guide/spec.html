Full specification

Required behavior

  1. Register test applications with both providers during preparation, configure exact callback URIs and test users, and keep client secrets outside source control. Teacher supplies a tested fallback cohort account when setup is unavailable.
  2. Google uses OpenID Connect: verify the ID-token signature with jose and discovery JWKS, permitted algorithms, issuer, audience, expiry and login-attempt nonce; key identity by issuer+sub.
  3. GitHub uses OAuth access token to retrieve the authenticated user; key by provider+numeric id, not mutable login name. Read /user/emails only with needed scope and select a verified email if one is required.
  4. Store a unique provider+subject mapping to a local member. First login creates a member after username onboarding; repeat login reuses it; no verified email means require local onboarding rather than invent one.
  5. Never auto-link by matching email. Linking requires an existing authenticated member, recent reauthentication and a separately bound link intent; the provider identity cannot already belong to another member.
  6. Issue the same P10 forum session after successful identity resolution. Access and refresh tokens are not rendered or placed in browser storage; discard provider tokens after profile use unless a documented server-side use requires retention.

Out of scope

Build this focused deliverable, not the complete forum. Features in the Level up chapter are optional and are not prerequisites unless the roadmap explicitly selects them. Do not replace a core learning task with a framework or finished service.

Use synthetic users and disposable test data during development. Keep a decision record when the brief allows a choice; the record must include an independently verifiable consequence.
