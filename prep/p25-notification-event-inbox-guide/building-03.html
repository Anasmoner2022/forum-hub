Step 3: Protect and render the inbox

Build recipient-only listing/read actions and deleted-target tombstones.

Questions before writing

  1. Which input and trusted context enter this component of Transactional Events and Notification Inbox?
  2. Which persisted or visible invariant must remain true if this step fails?
  3. An inbox ID is not authorization.

Guided build

  1. Write a small acceptance example for protect and render the inbox using this project's verification table.
  2. An inbox ID is not authorization.
  3. Resolve current target visibility rather than rendering an old private snapshot publicly.
  4. Implement the smallest boundary that satisfies that example; keep core logic in your own module and record your chosen policy.

Self-check

Another member cannot read or mark the recipient’s notification by changing an ID.

Evidence to keep

Keep the exact input, observed result and state/diagram evidence that make this self-check independently reviewable. If the result differs, trace the component before continuing.
