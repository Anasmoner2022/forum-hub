Full specification

Required behavior

  1. Model members, topics, replies, labels, topic-label membership, topic reactions, reply reactions and expiring server sessions.
  2. A topic has one author and one or more labels; a reply has one author and one topic; each member has one current reaction per target and at most one active session.
  3. Choose keys and identify candidate keys; normalized email is unique. Do not store labels as comma-separated strings or derived reaction counts as unexplained truth.
  4. Represent many-to-many relationships with junction tables; either separate reaction tables or enforce that exactly one target type is referenced.
  5. State deletion actions, nullability, reaction values, expiration units and which rules require a transaction rather than a single foreign key. Account credentials are sensitive hash records, never plaintext.

Inputs and output contracts

The output is the ERD/schema worksheet and supporting design documents; each review scenario is part of its contract.

Out of scope

Build this focused deliverable, not the complete forum. Features in the Level up chapter are optional and are not prerequisites unless the roadmap explicitly selects them. Do not replace a core learning task with a framework or finished service.

Use synthetic users and disposable test data during development. Keep a decision record when the brief allows a choice; the record must include an independently verifiable consequence.
