Full specification

Required behavior

  1. Require email, username and password; normalize email by trimming and lowercasing under an explicitly documented academy policy; reserve a unique normalized username.
  2. Email length is at most 254, username 3–30 characters matching letters/digits/underscore, and password 12–128 Unicode code points; enforce a 1024-byte password input cap before expensive work.
  3. Use asynchronous node:crypto scrypt with independent random salts and a versioned record. Training default: N=131072, r=8, p=1, output=64 bytes, salt=16 bytes, maxmem=256 MiB; measure feasibility before cohort launch.
  4. Use constant-time comparison of equal-length derived buffers, reject malformed records, bound concurrent expensive verification and return generic invalid-credentials messages.
  5. Never log raw passwords or hash records, never use reversible encryption for passwords, and rely on database uniqueness to settle competing registrations. BCrypt is an alternative only after equivalent prep and its byte-limit policy are reviewed.

Out of scope

Build this focused deliverable, not the complete forum. Features in the Level up chapter are optional and are not prerequisites unless the roadmap explicitly selects them. Do not replace a core learning task with a framework or finished service.

Use synthetic users and disposable test data during development. Keep a decision record when the brief allows a choice; the record must include an independently verifiable consequence.
