Full specification

Required behavior

  1. Show the signed-in member’s created posts, current likes and dislikes on posts and comments, and authored comments including comment text plus parent post title/link.
  2. Derive actor ID from the session; query parameters cannot select another member. Other actors’ private activity never appears.
  3. Explain the difference between current reaction state and event history. Cleared reactions disappear from the current-reactions section; switches move between like/dislike sections.
  4. Apply parent visibility and deletion policy: public links only to accessible content; owner-visible pending posts are labelled pending; deleted items show a neutral tombstone without leaking retained text.
  5. Use stable ordering by timestamp and ID, separate sections with 10-item pagination, bound inputs and avoid N+1 reads and multiplied aggregates.
  6. Record EXPLAIN QUERY PLAN on at least 1000 synthetic records, justify composite indexes for author/recipient/target queries, and keep correctness fixtures unchanged after optimization.

Out of scope

Build this focused deliverable, not the complete forum. Features in the Level up chapter are optional and are not prerequisites unless the roadmap explicitly selects them. Do not replace a core learning task with a framework or finished service.

Use synthetic users and disposable test data during development. Keep a decision record when the brief allows a choice; the record must include an independently verifiable consequence.
