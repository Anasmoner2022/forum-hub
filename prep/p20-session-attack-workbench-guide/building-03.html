Step 3: Inspect browser and error defenses

Run hostile forms/text, inspect policy headers and search logs for secret markers.

Questions before writing

  1. Which input and trusted context enter this component of Session Attack and Browser Defense Workbench?
  2. Which persisted or visible invariant must remain true if this step fails?
  3. CSP must match the actual page resources.

Guided build

  1. Write a small acceptance example for inspect browser and error defenses using this project's verification table.
  2. CSP must match the actual page resources.
  3. Keep no-store on private pages without forcing public pages to reveal session data.
  4. Implement the smallest boundary that satisfies that example; keep core logic in your own module and record your chosen policy.

Self-check

An injected payload remains literal and a copied revoked cookie cannot mutate anything.

Evidence to keep

Keep the exact input, observed result and state/diagram evidence that make this self-check independently reviewable. If the result differs, trace the component before continuing.
