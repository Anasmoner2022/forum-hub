Node.js and subject refresher

State binds a callback to the browser’s login attempt. PKCE binds the authorization code to a verifier. They solve different parts of the flow.

Browser → application /start → provider /authorize
Provider → application /callback?code=...&state=...
Application → provider /token (verifier, code, redirect URI)

Before implementing anything, predict the “Successful round trip” case: input matching browser, state, code and verifier, result one token result. Then contrast it with “Bad PKCE”.

Keep the boundary visible

  • beginLoginAttempt(db, browserId, provider, clock): Store a short-lived attempt and return the authorization URL.
  • consumeLoginAttempt(db, browserId, state, clock): Claim exactly one valid attempt or reject.
  • exchangeCode(provider, code, verifier): Resolve token response with no automatic replay.
