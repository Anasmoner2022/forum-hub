Full specification

Required behavior

  1. Create /auth/mock/start and /auth/mock/callback plus fake provider /authorize and /token endpoints on a separate local port.
  2. Generate unpredictable state and a PKCE verifier; store their digests/values as appropriate in a short-lived server login attempt bound to an HttpOnly SameSite=Lax browser cookie. Attempt TTL is 5 minutes.
  3. Send an S256 code challenge; exchange a one-time code server-to-server with the verifier and exact registered redirect URI. Client secrets remain server-side.
  4. Callback requires matching state, browser binding and unexpired unused attempt. Atomically claim/consume the attempt before exchange; a replay cannot exchange again.
  5. Handle user denial, bad state, expired attempts and token failure without creating a session. Local fake HTTP is a learning fixture; real-provider endpoints use HTTPS.

Out of scope

Build this focused deliverable, not the complete forum. Features in the Level up chapter are optional and are not prerequisites unless the roadmap explicitly selects them. Do not replace a core learning task with a framework or finished service.

Use synthetic users and disposable test data during development. Keep a decision record when the brief allows a choice; the record must include an independently verifiable consequence.
