Full specification

Required behavior

  1. Accept exactly one file field named image plus title, body, csrf and 1–5 repeated category fields from a native multiple select; require authentication before receiving the upload. Reject unsafe Origin before parsing, then validate the bounded csrf field before publishing anything.
  2. Support multipart/form-data only; use Busboy rather than writing a multipart parser. Limit fields to 8, fieldSize to 16 KiB, files to 1, parts to 9 and whole request to 21,000,000 bytes. Reject unknown field names and collect repeated category values before validating distinct IDs.
  3. The source says 20 mb; academy defines the exact per-file limit as 20,000,000 bytes (decimal MB). Accept at the limit and reject one byte above with 413 and a clear image-too-big message.
  4. Do not trust Content-Length alone. Enforce file-stream byte limit, parser truncation/limit events, total request byte count, timeouts and client abort handling.
  5. Write provisional files under a private temp directory using generated names, never client filenames. Failure, missing/wrong CSRF or abort removes all temp files and creates no public record.

Out of scope

Build this focused deliverable, not the complete forum. Features in the Level up chapter are optional and are not prerequisites unless the roadmap explicitly selects them. Do not replace a core learning task with a framework or finished service.

Use synthetic users and disposable test data during development. Keep a decision record when the brief allows a choice; the record must include an independently verifiable consequence.
