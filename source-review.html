Adaptations made explicit

  • Go-or-Node.js team choice replaces source Go-only language restrictions. Worked preparation and starter code use Node.js.
  • ERD is a submitted deliverable and password hashing is a baseline requirement, even where the source makes them recommendations/bonuses.
  • Source “password encryption” is implemented as one-way password hashing; live database encryption remains a separate optional SQLCipher track.
  • Source 20 mb becomes exactly 20,000,000 bytes; dimensions, animation and whole-request budgets are defined for testable resource limits.
  • CSRF, ownership/recipient checks, concurrency conflicts, cleanup and repeatable verification are explicit academy contracts, prepared before integration.
  • Notifications are durable stored inbox items. The source learning outcome mentions real-time, but its required feature list does not specify a push protocol; SSE/WebSockets remain elective and require separate prep.
  • Go-specific goroutines/channels are not mandatory Node APIs; the Node route practices promises, streams and transaction/concurrency boundaries for the same behavior.
  • Optional extensions can branch independently from F01; integrated combinations receive explicit regression obligations.

Review limitations and cohort research

This delivery verifies guide structure, local navigation, prerequisite coverage and scaffold syntax. It intentionally leaves implementation logic to learners and does not claim to have built/tested all learner solutions or registered provider applications. The instructor preflight covers live setup, native-driver compatibility and timing estimates. Primary references support the technology choices; field lengths, timeouts, pixel budgets and the rubric are authored academy policies.
