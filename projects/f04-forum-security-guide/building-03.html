Step 3: Run session and browser attacks

Use P20 fixtures against real forum routes, then run all installed regressions.

Questions before writing

  1. Which input and trusted context enter this component of Forum Security: HTTPS, Limits and Session Defense?
  2. Which persisted or visible invariant must remain true if this step fails?
  3. Check state after a failed attack.

Guided build

  1. Write a small acceptance example for run session and browser attacks using this project's verification table.
  2. Check state after a failed attack.
  3. Rotate privileges through the same server-state policy used for authorization.
  4. Implement the smallest boundary that satisfies that example; keep core logic in your own module and record your chosen policy.

Self-check

Forged/expired/revoked tokens and CSRF payloads never create unauthorized content.

Evidence to keep

Keep the exact input, observed result and state/diagram evidence that make this self-check independently reviewable. If the result differs, trace the component before continuing.
